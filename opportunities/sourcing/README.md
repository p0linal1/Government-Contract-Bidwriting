# FGA-first intake — sourcing → pick → file → intake

The **FGA-first** path finds opportunities by our capability codes instead of waiting for an
email. It complements the Gmail poller (`bin/bid-inbox.sh`); either can start a bid. Everything
runs off the in-tree `secrets/` (tokens self-refresh) — no per-run login once bootstrapped.

## The flow

### 1. Source (scheduled or on demand) — `bin/bid-source.sh`
Searches the FGA portal for open opportunities matching `company/sourcing.json` (our NAICS/PSC
codes, each widened by the last digit), screens out what we can't bid (excluded set-asides,
sole-source/intent-to-award titles, excluded notice types, anything closing in < `min_days_to_due`),
and writes a dated report here under `fga/`, with **what is NEW since the last run** at the top.

```
bin/bid-source.sh                 # normal run: new-since-last-time
bin/bid-source.sh --all           # report everything as new (ignore seen-state)
bin/bid-source.sh --since-days 7  # only opportunities posted in the last 7 days
```
Output: `fga/report-<date>.md` (human), `fga/latest.json` / `fga/latest.csv` (machine),
seen-state in `inbox/fga-seen.json`. On macOS it posts a desktop notification when there's
something new. Schedule it weekday mornings (see the header of `bin/bid-source.sh` for the cron line).

### 2. Triage — read `inbox/sourcing-queue.md` (auto-generated by the source step)
`bin/bid-source.sh` runs `bidkit.triage` after every search, scoring each match on two axes and
sorting them into **keep / borderline / reject**:
- **Value** — from FGA's estimate (labelled as FGA's, never the agency's), with a confidence.
  Auto-**reject** at ≥ $20M (can't perform as a small prime — the "$200M contract" case) and a
  low score below the worthwhile-bid threshold.
- **Eligibility** — from NAICS/PSC (core-software seed vs off-seed) + a custom-software title
  signal (develop / implement / modernize / migration / API …) minus non-software signals
  (hardware / landscaping / construction — the "hedge-trimming" case), with a confidence.
- **Verdict**: `reject` (too big / out-of-scope / closed / non-competition type — auto-screened),
  `borderline` (plausible, skim first), `keep` (worth the deep evaluation).

This is a **shallow first-pass on FGA's own data** — a `keep` means "worth the deep four-line
value triangulation" (`bid-intake.md` step 4b), **not** a go/no-go. Confidence is capped at MEDIUM.
Every score carries its source and confidence; the reject bucket is grouped by reason so you can
audit it. `inbox/sourcing-queue.csv` is the machine-readable companion. Thresholds and the
title-signal patterns live in `company/sourcing.json` → `triage` — tune them there.

Read the **KEEP** section first, then skim **BORDERLINE**. The full portal report
(`fga/report-<date>.md`) remains the complete unscored record if you want to see everything.
Judgement call — the tooling does not decide.

**The resale screen already removes most COTS noise.** `sourcing.json` carries
`resale_title_patterns` (renewal / subscription / license / perpetual / upgrade / …) and a
protecting `keep_title_patterns` (develop / implement / modernize / replacement / professional
services / application maintenance / …). A title matching a resale word is dropped **only if it
does not also match a keep word**, so branded renewals (Autodesk, Verkada, Mimecast, SAP, VMware,
…) are screened out while real work ("CAD System Replacement", "LIMS … Implementation", "Website
Modernization … Professional Services", "Application Maintenance and Support") is kept. Dropped
rows are **counted transparently** in the report header under `screened out: … resale/COTS renewal (N)`
— nothing vanishes silently, so you can audit the screen. On the 2026-09-28 run it removed ~74 of
~690. It is a **soft** screen: tune the two lists in `sourcing.json` when you spot a miss, and bias
toward keeping (a false negative — dropping a real bid — is worse than a little noise). Setting
either list to `[]` turns the screen off. Still eyeball the report for anything that slipped
through (e.g. hardware-only buys).

### 3. Promote a keeper — `bin/bid-file.sh <fga-opportunity-id>`
Promoting a `keep` (or an interesting `borderline`) from the **sourcing queue** into a filed
opportunity is what moves it onto the **evaluation queue**:
- `inbox/sourcing-queue.csv` = unfiled FGA candidates (hundreds, machine-triaged).
- `inbox/evaluation-queue.csv` = filed opportunity folders worth a human go/no-go (a short list).
- `bin/bid-file.sh` is the bridge: it files the chosen candidate as `opportunities/<id>/` and it
  then belongs on the evaluation queue.

The id is the UUID in the row's portal deep link
(`…/opportunities/view/<id>?tab=opportunities`), also the `fga_id` column in the CSV.

```
bin/bid-file.sh 31b1e9f2-84be-420b-a8e0-9d868e4de60e
```
Creates `opportunities/<number>-<slug>/` with:
- `opportunity.json` (source.type = fga)
- `rfp/portal-record.json` + `.md` — the portal's own record (the shape `bidkit.brief` reads)
- `rfp/<documents>` **when FGA serves them** — often it doesn't (its links 403); then
  `rfp/portal-fetch.md` says "no documents attached on the portal"
- `sourcing/fga-record.md` — FGA's summary + the SOURCE-system URL, agency, contact, value estimate
- `initial-email/links.md` — the SOURCE-system + aggregator URLs (no email exists for a sourced opp)
- `opportunity-facts.md` + `research/research-plan.md` + `calendar.ics` (brief + calendar run automatically)

### 4. Fetch documents from the SOURCE system (usually required)
Because FGA rarely attaches the actual RFP, open `initial-email/links.md` and download the RFP and
all attachments into `rfp/` from the source portal (SAM.gov, the agency's own portal, WEBS, etc.).
For WEBS sources, `python3 -m bidkit.portal fetch` can pull them (see `bid-tooling.md`); otherwise
download by hand. Verify each file (`pdf_verify` / `xlsx_verify`).

### 5. Intake — in Kiro
```
run intake on opportunities/<the folder bid-file.sh printed>
```
From here it is the standard intake workflow (`bid-intake.md`): read the RFP + addenda, confirm
the schedule (the sourced dates are DETECTED — `confirmed: false`), run the four-line value
triangulation, and produce the go/no-go summary.

## Notes
- **Codes live in `company/sourcing.json`**, never in the tooling. To change what we source for,
  edit that file (and keep `company/capability.json` + `company-profile.md` in sync).
- **CAGE/UEI are not sourcing filters** — FGA searches opportunities by NAICS/PSC + set-aside.
  CAGE/UEI identify the company on registrations and bid forms.
- **Push our codes to the FGA business profile** (optional, so the portal UI also reflects them):
  `cd bidkit && python3 -m bidkit.fga --portals ../inbox/portals.json profile --criteria ../company/sourcing.json`
  (dry run; add `--apply` to write, a backup is saved first).
- **Auth**: tokens in `secrets/fga-tokens.json` self-refresh. If expired:
  `cd bidkit && python3 -m bidkit.fga --portals ../inbox/portals.json login --auto` (uses `secrets/env`).
